## 1. 现状判断

### 1.1 已经具备的

- 完整的功能地图：任务、组织体系、6 类视图、提醒/重复、专注、习惯、纪念日、笔记、统计、跨平台能力。
- 免费版 / 高级会员的能力对照，以及“取消限额、云端能力本地替代”的策略。
- 一份概念级数据模型（Profile / Folder / Project / Task / Habit / Focus / Countdown 等）。
- P0–P3 的功能优先级和一份验收清单。
- 98 篇原始帮助文档，可作为规则核对底稿。

### 1.2 还缺的

| 缺口 | 说明 | 影响 |
|---|---|---|
| 可执行的产品范围 | “大部分功能”没有定义 Must / Should / Won't，也没有平台边界 | 范围失控，无法排期 |
| 规则规格 | 帮助文档描述“能做什么”，不描述边界条件、算法和冲突处理 | 重复、时区、提醒等核心模块无法验收 |
| 数据字典与 Schema v1 | 现有模型是概念图，缺表、字段类型、约束、索引、迁移、软删除、排序 | 无法写第一行业务代码 |
| 交互规格 | 缺页面清单、状态、拖拽矩阵、右键菜单、快捷键、批量操作、空态/错误态 | UI 会反复返工 |
| 技术架构 | 未定平台、框架、存储、通知调度、富文本、搜索、NLP、MCP/CLI 形态 | 选型错误会导致后期重写 |
| 测试基线 | 没有重复规则、农历、节假日、时区、中文 NLP 的测试语料 | 核心正确性无法保证 |
| 数据交换格式 | 自有备份格式、CSV/ICS 字段映射、第三方导入适配器未定义 | 数据迁移和互操作受阻 |
| 法务与品牌 | 视觉、图标、文案、第三方数据许可证未确认 | 上线风险 |

### 1.3 关键判断

**“无需会员”是最容易实现的部分。** 本地优先架构天然没有配额；真正难的是：

1. **重复任务引擎**（到期重复 / 完成重复 / 自选日期 / 农历 / 法定工作日 / 艾宾浩斯 / 单周期例外 / 时区与 DST）。
2. **中文自然语言日期识别**（“明早十点”“下周五”“农历八月十五”“提前 30 分钟提醒”）。
3. **跨平台可靠提醒**（应用关闭、休眠、勿扰、持续提醒、错过提醒后的补偿）。
4. **数据安全**（升级迁移、备份恢复、附件、崩溃恢复）。
5. **范围控制**（协作、微信、原生小组件等长尾能力极易拖垮项目）。

## 2. 先把“大部分功能”定义清楚

建议把 v1 定义为“单机个人时间管理闭环”，而不是“滴答清单全功能克隆”。

### 2.1 建议的 v1 范围

| 能力域 | v1 | 后续 | 不做/替换 |
|---|---|---|---|
| 任务 | 增删改查、子任务、检查事项、优先级、标签、附件、评论、模板、完成/放弃/垃圾桶 | 任务合并、复杂分享图片 | — |
| 组织 | 文件夹、清单、分组、二级标签、过滤器、智能清单 | 多档案 | — |
| 视图 | 列表、看板、日历（日/周/月/年/日程/列表）、四象限、时间线 | 课表 | — |
| 时间 | 日期/时间段/全天/跨天、提醒、重复、农历、法定节假日 | 位置提醒（移动端） | — |
| 模块 | 番茄专注、习惯打卡、倒数纪念日、笔记/摘要 | 白噪音扩展、严格模式 | — |
| 数据 | 本地 SQLite/OPFS、JSON 全量备份、通用 CSV/ICS 导入导出 | 第三方应用导入 | 滴答 CSV 专用兼容 |
| 集成 | 本地通知、URL Scheme、CLI、本地 MCP | 自带 Key 的 AI、浏览器插件、邮件转任务、Notion | 微信生态 |
| 协作 | 单档案 | 自建同步、共享清单 | 微信/QQ 登录、官方云 |
| 平台 | Windows 桌面 + Web/PWA（v1 并行） | macOS/Linux、移动端 | 鸿蒙/手表首发 |

> 如果“共享协作”是刚需，应单独作为 v2 项目立项，因为它会反向要求账号体系、服务端、权限模型和冲突合并，不能顺手做。

### 2.2 平台顺序建议

1. **Windows 桌面（Tauri）+ Web/PWA 并行（v1）**：共享 UI 与领域层；桌面验证通知/快捷键/便签，Web 验证离线本地库/PWA。
2. **macOS/Linux**：Tauri 同一代码库补齐打包与通知适配（v1.1）。
3. **移动端**：桌面与 Web 稳定后再做；优先考虑 Capacitor 复用 Web UI，或 React Native 重做交互层。

理由：桌面端最容易实现“本地优先 + 系统通知 + 全局快捷键 + 文件附件”；Web/PWA 覆盖跨平台与轻量使用。两者并行会带来存储适配和通知降级成本，必须在 M0 做技术验证。

## 3. 开工前必须补齐的规格

### 3.1 领域规则（最高优先级）

以下规则不能只写“支持”，必须写成可测试的判定表 / 状态机 / 伪代码。

#### 3.1.1 重复任务

必须明确：

- 数据模型：重复“系列（series）”与“实例（occurrence）”的关系；是否物化未来实例。
- 重复类型：每天 / 每周 / 每月 / 每年 / 每周工作日 / 法定工作日 / 每周末 / 法定节假日 / 农历每年 / 农历每月 / 艾宾浩斯 / 自定义三种。
- 到期重复 vs 完成重复：下次时间基于“计划时间”还是“完成时间”；拖延、提前完成如何处理。
- 结束条件：按日期、按次数；次数是否包含首次。
- 单周期操作：仅此周期、跳过此周期、修改未来所有、恢复默认。
- 例外：EXDATE / 覆盖字段 / 单周期改期后是否保留原规则。
- 时区与 DST：固定时间 vs 固定时区；跨时区后“每天 9 点”如何漂移；不存在/重复的本地时间如何处理。
- 全天与跨天：全天任务用本地日期存储，不能存 UTC 零点。
- 农历：闰月、三十/廿九、除夕、生日“忽略年份”、农历每月初一/十五。
- 法定工作日/节假日：年度数据来源、调休、数据更新机制。
- 艾宾浩斯：1,2,4,7,15,15… 的锚点是首次日期还是完成日期；与结束条件组合。
- 完成语义：完成当前实例后生成下一实例；父任务/子任务级联；检查事项全完成是否自动完成主任务。
- 错过周期：应用离线/未打开期间错过的重复实例，是补生成、跳过还是只生成最近一个。
- 搜索/日历/看板中的重复展开窗口与上限。

**建议**：不要直接用 `rrule.js` 硬套全部场景。采用“标准 RRULE 子集 + 自定义规则 JSON + 展开器”的混合方案，并为每个规则写属性测试。

#### 3.1.2 智能清单

帮助文档只写了表面规则，必须补充：

- “今天”是否包含逾期任务（官方行为需要用真实账号验证；这直接决定产品手感）。
- “明天”“最近 7 天”的区间边界（含今天？含逾期？）。
- 收集箱：是特殊清单还是 `projectId = null`；能否删除/隐藏。
- 已完成 / 已放弃 / 垃圾桶的保留期、恢复规则、批量清空。
- 智能清单中是否显示习惯、纪念日、专注记录（可配置项）。
- 排序、分组、筛选在智能清单中的默认值。

#### 3.1.3 四象限

- 方案 1（优先级）的精确定义：高→重要且紧急，中→重要不紧急，低→紧急不重要，无→不重要不紧急；需要确认“低”和“无”的映射是否与文档一致。
- 方案 2（时间 + 优先级）的“紧急”阈值：今天/明天算紧急？未来 7 天？无日期算不紧急？
- 自定义规则：多条件为“且”；一个任务可命中多个象限时的显示策略。
- 拖动到其他象限时，究竟修改哪些字段（优先级？日期？两者？）；规则冲突时如何提示。
- 象限排序、已完成/检查事项显示、打印/分享。

#### 3.1.4 过滤器

需要定义一个可序列化的查询 DSL，例如：

```json
{
  "op": "AND",
  "children": [
    { "field": "projectId", "op": "in", "value": ["..."] },
    { "field": "tags", "op": "all", "value": ["..."] },
    { "field": "dueDate", "op": "between", "value": ["2026-11-05", "2026-11-12"] }
  ]
}
```

必须明确：

- AND / OR 的优先级与嵌套层级（UI 是否只支持一层）。
- 同一条件内标签的“且/或”语义。
- 日期预设（今天、最近 7 天、已过期、无日期）的运行时解析规则。
- 关键词匹配范围（标题、正文、检查事项、评论）与分词方式。
- 默认排除已完成/已删除；用户能否显式包含。
- 保存为过滤器后的版本兼容（DSL 升级）。

#### 3.1.5 提醒

- 提醒是独立表还是任务内 JSON；修改任务时间后如何重算。
- 多提醒、结束时间提醒、提前/延后偏移。
- 稍后提醒的默认时长、可配置范围。
- 应用未运行/系统休眠/错过提醒后的补偿策略（补弹、静默、标记错过）。
- 持续提醒在各平台的降级方案（桌面托盘循环通知；Web 只能普通通知）。
- 按优先级铃声、免打扰、通知权限被拒绝时的提示。
- 重复任务的提醒如何随实例生成。

#### 3.1.6 习惯

- 频率判定：每天、每周 N 次、每月 N 次、每 N 天、指定星期；周期边界按自然周/自然月还是滚动窗口。
- 目标与打卡量：目标单位、每次增量、超额是否累计、未达标是否算打卡。
- 三种打卡方式的状态机：自动记录 / 手动记录 / 完成全部。
- 补记、修改历史、删除记录后的统计重算。
- 连续天数、完成率、热力图、周/月统计的精确定义。
- 归档/恢复/删除对历史记录的影响。
- 提醒与日历时间轴的映射。

#### 3.1.7 倒数纪念日

- 公历/农历转换、闰月、2 月 29 日。
- “忽略年份”与“显示岁数”的组合。
- 倒计时 / 正计时的启用条件。
- 天数计算：标准 vs 当天算第 1 天；跨时区。
- 每年重复、每月第 X 个星期几、每月 X 日等自定义规则。
- 置顶只能一个、分组、归档、智能清单显示级别。

#### 3.1.8 专注

- 计时器状态机：idle / running / paused / finished / abandoned；应用重启后恢复。
- 番茄模式与正计时；专注中加时/减时；休息阶段是否记录。
- 关联任务/习惯/常用专注；删除关联对象后的历史记录处理。
- 补记、编辑时长、批量删除。
- 统计口径：总时长、按天/周/月、最佳时段、热力图、按任务/清单/标签分布。
- 白噪音、沉浸模式、严格模式（平台相关，v1 可降级）。

#### 3.1.9 笔记、摘要、搜索、成就

- 富文本格式：建议 Markdown 为唯一真源，编辑器用 ProseMirror/TipTap；附件独立存储。
- 笔记无“完成”概念；任务 ↔ 笔记转换的限制（带子任务不能转）。
- 摘要的筛选、排序、分组、导出图片/文本、模板。
- 搜索：中文分词/三元组、拼音搜索是否要做、FTS 索引更新策略、搜索范围。
- 成就值：官方公式未公开。建议自定义一套透明公式并写进产品文档；VIP 勋章改为使用时长/连续使用等非付费勋章。

### 3.2 数据字典与 Schema v1

现有概念模型需要落成可迁移的 schema。至少补齐：

- 所有业务表带 `profileId`（为多档案预留；v1 只创建一个档案）。
- 桌面用 SQLite，Web 用 SQLite-WASM + OPFS 或 IndexedDB 适配器；领域层不感知存储差异。
- 主键使用 UUIDv7（时间有序，便于同步/分页）。
- 软删除：`deletedAt`；垃圾桶保留期与彻底删除。
- 排序：不要用浮点 `order` 长期硬扛，建议 fractional indexing（字符串 rank）或定期重排。
- 日期：
  - 全天/日期型字段存 `YYYY-MM-DD` + 时区模式，不存 UTC 零点。
  - 时间型字段存 UTC 时间戳 + IANA 时区 + 原始本地时间（用于固定时间语义）。
- 重复：`recurrence_series`、`recurrence_exception`、`original_occurrence_at`。
- 提醒：独立 `reminder` 表，含绝对触发时间、偏移、状态（pending/fired/snoozed/dismissed）。
- 标签：`tag` + `task_tag` 多对多；二级标签用 `parentId`。
- 检查事项：独立表，含 `completedAt`、`order`、独立提醒。
- 评论/动态：独立表，含 actor、action、field、old/new value。
- 附件：元数据表 + 内容寻址文件（hash 命名），避免重命名/移动导致失效。
- 设置：按 profile 存 JSON，但需版本号与默认值合并策略。
- 日历订阅：账号、同步游标、事件、重复例外。
- 全文索引：SQLite FTS5；中文建议 `trigram` 或预分词。
- 变更日志：`change_log`（entity、entityId、op、payload、deviceId、seq），为未来同步预留，避免后期重写。
- 迁移：`schema_migrations` 表 + 单向迁移脚本 + 备份后迁移。

**关键取舍**：即使 v1 不做多端同步，也建议从第一天保留 `deviceId`、`updatedAt`、`deletedAt`、`change_log`。否则未来加同步要重构全部写入路径。

### 3.3 交互规格

至少产出：

- 页面清单：桌面侧边栏、任务列表、任务详情、快速添加、日历各视图、看板、时间线、四象限、专注、习惯、纪念日、笔记、搜索、过滤器、设置、垃圾桶。
- 每个页面的状态：加载、空、错误、无权限、离线、超长内容。
- 拖拽矩阵：任务拖到清单/标签/智能清单/子任务/看板列/日历/象限，分别改什么字段。
- 批量操作：多选、框选、Shift/Ctrl 选择、批量改期/移动/标签/完成/删除。
- 右键菜单与快捷键：与官方“功能等价”即可，键位可原创；支持 `?` 查看快捷键。
- 撤销/重做：至少覆盖删除、完成、移动、批量操作。
- 移动端手势：左滑/右滑、长按、下拉；与桌面共用业务规则。
- 无障碍：键盘可达、焦点顺序、屏幕阅读器标签、对比度、减少动效。

### 3.4 非功能指标

建议先定下可验收的目标：

| 指标 | 建议目标 |
|---|---|
| 启动时间 | 冷启动 < 2s（10 万任务） |
| 列表滚动 | 10 万任务虚拟列表 60fps |
| 搜索 | 10 万任务关键词搜索 < 150ms |
| 保存 | 单任务保存 < 50ms（本地） |
| 数据安全 | 自动备份 + 迁移失败可回滚 |
| 崩溃恢复 | 未保存编辑最多丢失 5s |
| 离线 | 桌面与 Web/PWA 除订阅外全部可用 |
| 安装包 | Windows < 30MB（Tauri 目标） |
| Web 首屏 | 宽带 < 2s；PWA 二次打开 < 1s |
| 遥测 | 默认关闭，可选匿名崩溃报告 |

### 3.6 数据交换

- 自有格式：版本化 JSON（全量、含附件清单、校验和）+ 通用 CSV（互操作）。
- 导入适配器接口：`detect(file) -> preview -> map -> import -> report`。
- 首批适配：自有备份、通用 CSV、ICS。
- 不做滴答清单 CSV 专用兼容；第三方应用导入（Todoist/Microsoft To Do）放到 v1.1。
- 导出：JSON、CSV、ICS；日历反向订阅可后置。
- 所有导入必须有 dry-run 预览、冲突策略（跳过/覆盖/新建）、错误报告。

### 3.7 测试基线

- **重复规则**：属性测试（生成随机规则，验证下次时间单调、终止条件、无死循环、DST 边界）。
- **农历/节假日**：固定年份 golden cases（春节、中秋、闰月、除夕、调休）。
- **中文 NLP**：200+ 条真实语料，标注期望解析结果与文本 span。
- **时区**：跨时区、DST 前后、全天任务、固定时间/固定时区。
- **数据层**：迁移、备份/恢复、崩溃恢复、10 万任务性能。
- **E2E**：添加→排期→提醒→完成→重复生成→垃圾桶恢复。
- **平台通知**：Windows/macOS/Linux 各一轮手工清单。

### 3.8 法务与品牌

- 视觉语言与滴答一致：布局层级、信息密度、主要交互路径可以对齐；不做像素级复制。
- 不复制名称、Logo、图标、插画、文案、主题、铃声、字体；使用原创或开源授权资产。
- 建议自建 design tokens，保证“像滴答但仍是另一个产品”。
- 第三方库许可证审计（农历、节假日、富文本、日历、拖拽、图标）。
- 节假日/农历数据源的商用许可与年度更新责任。
- 隐私说明：数据默认本地；敏感配置存系统钥匙串/浏览器安全存储；不默认上传。
- 不调用官方私有 API、不绕过官方鉴权、不内置官方付费内容。

## 4. 建议技术方案

### 4.1 推荐栈

| 层 | 建议 | 理由 |
|---|---|---|
| 桌面壳 | Tauri 2 | 体积小、原生通知/托盘/快捷键/多窗口；Rust 侧可做文件与调度 |
| UI | React + TypeScript + Vite | 生态成熟，Web/PWA 复用 |
| 样式 | Tailwind + 自建 design tokens | 对齐滴答的布局/密度/色彩语义，资产原创 |
| 状态 | TanStack Query + Zustand | 查询缓存 + 轻量 UI 状态 |
| 本地库 | 桌面 SQLite（WAL）+ FTS5；Web SQLite-WASM + OPFS | 尽量复用同一套 SQL/领域层；Web 需 M0 验证 |
| 数据访问 | 领域层 Repository 接口 + 桌面/Web 两个适配器 | 隔离 Tauri SQLite 与浏览器存储差异 |
| 富文本 | TipTap/ProseMirror + Markdown 真源 | 可扩展、可导出、可搜索 |
| 拖拽 | dnd-kit | 列表/看板/日历统一 |
| 虚拟列表 | TanStack Virtual | 10 万任务性能 |
| 日期 | date-fns + date-fns-tz | 轻量；复杂时区逻辑自写测试 |
| 重复 | 自研展开器 + rrule 子集 | 农历/节假日/完成重复无法直接套 RRULE |
| 农历 | lunar-typescript（6tail） | 成熟；需做许可证与边界测试 |
| 节假日 | 年度 JSON 数据（自建/开源数据） | 避免运行时依赖；可更新 |
| 中文 NLP | 规则语法 + chrono-node 基线 + 自建语料 | 可控、离线、可解释；后续可接 LLM |
| 通知 | 桌面：Tauri notification + 托盘调度器；Web：Notification API + Service Worker | 需逐平台验证关闭应用/浏览器后的可靠性 |
| PWA | vite-plugin-pwa / Workbox | 离线缓存、安装、更新提示 |
| AI（v1.1） | Provider 抽象：OpenAI 兼容 / Ollama / 本地 Whisper | 自带 Key，无额度 |
| CLI/MCP | 本地 HTTP/JSON-RPC 服务 + Node CLI / MCP Server | 复用领域层，避免规则重复实现 |
| 测试 | Vitest + Playwright + fast-check | 单元、E2E、属性测试 |
| 打包 | Tauri bundler + 自动更新；Web 静态托管 | Windows/macOS/Linux + PWA |

### 4.2 建议仓库结构

```text
apps/
  desktop/          # Tauri + React（v1）
  web/              # PWA（v1，复用 packages/ui）
  mobile/           # v2
packages/
  core/             # 领域模型、用例、规则（纯 TS）
  db/               # schema、迁移、Repository 接口
  db-sqlite/        # Tauri/Node SQLite 适配器
  db-web/           # SQLite-WASM/OPFS 或 IndexedDB 适配器
  ui/               # 组件库、design tokens
  recurrence/       # 重复规则解析与展开
  nlp/              # 中文日期/重复/提醒识别
  calendar/         # 日历视图与 ICS
  integrations/     # 导入导出、订阅（AI 在 v1.1 加入）
  mcp/              # 本地 MCP Server
  cli/              # 命令行
docs/
  research/
  plan/
  specs/            # 规则规格、数据字典、交互稿
```

### 4.3 几个关键工程决策

1. **领域层不依赖 UI 和 Tauri**：所有规则可在 Node 中单测，CLI/MCP 直接复用。
2. **重复任务不预生成无限实例**：只物化当前窗口；日历按需展开；单周期例外单独存。
3. **提醒存绝对触发时间**：任务时间/时区/偏移变化时重算；启动时扫描 `pending` 且已过期的提醒，按策略补发。
4. **全天日期用本地日期字符串**：避免 UTC 偏移导致“日期跳一天”。
5. **附件内容寻址**：文件名变化不影响引用；备份时单独打包。
6. **从第一天保留同步元数据**：即使 v2 才做同步。
7. **写路径统一走用例层**：禁止 UI 直接改表，便于审计、撤销、变更日志和未来同步。
8. **MCP/CLI 不直连数据库写**：通过本地服务调用同一套用例，避免规则分叉。
9. **Web 与桌面共享领域层，不共享存储实现**：Repository 接口 + 两个适配器；UI 不写 SQL。
10. **视觉对齐用 tokens，不用截图**：颜色、间距、字号、圆角、密度定义成 token；图标与插画使用原创/开源资产。
11. **v1 单档案但不写死**：所有用例接收 `profileId`，启动时取当前档案；为 v1.1 多档案留口。

## 8. 主要风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 重复/时区 | 规则组合爆炸，DST 和跨时区最易出错 | 先写规格与属性测试，再写 UI |
| 中文 NLP | 用户期望高，边界多 | 规则解析 + 可解释高亮 + 手动兜底 + 语料回归 |
| 通知可靠性 | 应用关闭/休眠/权限限制；Web 关闭浏览器后不可靠 | 每个平台先做技术验证；托盘常驻 + 补偿策略；Web 明示限制 |
| Web 存储 | SQLite-WASM/OPFS 兼容性、FTS5、配额、性能 | M0 做 spike；失败则 IndexedDB 适配器；附件限额 |
| 范围蔓延 | 协作、微信、原生组件极易拖垮进度 | 明确 Won't，v2 再立项；Web/PWA 与桌面共享领域层 |
| 数据丢失 | 迁移/备份/附件是信任基础 | 自动备份、迁移回滚、恢复演练 |
| 性能 | 本地无限额后数据量可能很大 | 虚拟列表、FTS、分页、附件配额 |
| 首屏体积 | 农历/日历等重模块可能拖慢首屏 | 农历库已按需加载：主 JS 约 310KB，农历 chunk 约 301KB |
| 法务 | UI/图标/数据许可证；视觉相似度 | 视觉语言一致但资产原创；许可证审计；隐私说明 |
