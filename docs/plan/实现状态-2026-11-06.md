# Dayline v1 实现状态（2026-11-06）

## 用户管理（本地多用户）

- 侧边栏底部显示当前用户，点击打开“用户管理”。
- 支持创建、切换、重命名、删除用户；至少保留一个用户。
- 每个用户使用独立的 SQLite 数据库文件：`dayline-user-<id>.sqlite3`；早期默认用户继续使用 `dayline.sqlite3`，已有数据不会丢失。
- HTTP 局域网访问（OPFS 不可用）时，每个用户使用独立的 localStorage 键，自动备份也按用户隔离。
- 删除用户会关闭其数据库连接，删除 OPFS 文件或 localStorage 键，并清理该用户的自动备份。
- 新用户默认创建空收集箱；默认用户保留示例数据。

## 数据层

`AppState` 已扩展并接入 SQLite 行映射：

- `folders`
- `filters`
- `templates`
- `comments`
- `attachments`
- `habits` / `habitCheckins`
- `focusSessions`
- `countdowns`

`SqliteRepository.replaceAll()` 支持备份恢复与撤销/重做，按外键顺序写入并处理父子任务顺序。

## 数据可靠性与附件存储

- SQLite 驱动增加临时 `SQLITE_BUSY / LOCKED / IOERR` 重试（最多 4 次，指数退避）。
- 设置页增加“检查数据库完整性”（`PRAGMA quick_check`）。
- 恢复 JSON 备份前自动写入一份本地快照，可回滚。
- 附件从 SQLite Data URL 升级为内容寻址存储：
  - 安全上下文（localhost/HTTPS）优先写入 OPFS：`attachments/<profile>/<sha256>`。
  - HTTP 局域网回退到 IndexedDB，仍可刷新保留。
  - 旧 Data URL 附件在启动/恢复后自动迁移。
  - 图片内联预览、下载、删除时清理无引用文件。
  - JSON 备份会把附件重新内联为 Data URL，保证跨设备可恢复。

## 已知限制

1. 农历重复：`lunar-typescript` 仅在 Web 端按需加载，重复引擎尚未注入农历转换器；当前农历用于节日标签和纪念日换算。
2. 日历订阅：仅支持 ICS 文件导入导出，URL 订阅受 CORS/鉴权限制，未接。
3. 时区：字段存在但未提供固定时区/辅助时区 UI。
4. 持续提醒、按优先级铃声、错过补偿策略未接。
5. 清单内 section 分组、列表精确拖拽排序未接。
6. Tauri 桌面端：Rust stable 已安装，但本机仍缺 MSVC Build Tools / Windows SDK，暂不能编译。
7. 附件备份会显著增大 JSON 体积；超大附件建议单独归档。
