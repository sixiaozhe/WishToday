# 智能清单与过滤器规格 v1

> 配套：`docs/specs/数据字典与Schema-v1.md`
> 目标：把“今天/收集箱/过滤器”从 UI 概念变成确定的查询语义
> 日期：2026-11-05

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| 智能清单 | 由固定规则生成的虚拟任务列表，不存任务 |
| 过滤器 | 用户保存的自定义查询，侧边栏常驻 |
| 活跃任务 | `status='open'` 且 `deleted_at IS NULL` |
| 逾期 | `start_date < today` 且任务仍活跃 |
| 无日期 | `start_date IS NULL` |
| 完成 | `status='completed'` |
| 放弃 | `status='abandoned'` |
| 跳过 | `status='skipped'`（重复周期跳过） |
| 垃圾桶 | `deleted_at IS NOT NULL` |

所有日期比较使用**档案时区的本地日期**，不是 UTC 日期。

---

## 2. 智能清单

### 2.1 规则表

| 智能清单 | 规则 | 排序 | 说明 |
|---|---|---|---|
| 收集箱 | 活跃任务，且 `project.is_inbox=1` | 手动/日期 | 每档案唯一，不可删除 |
| 今天 | 活跃任务，且 `start_date <= today` | 逾期在前，再按时间/优先级 | **包含逾期**（本复刻决策） |
| 明天 | 活跃任务，且 `start_date = tomorrow` | 时间/优先级 | 不含逾期 |
| 最近 7 天 | 活跃任务，且 `start_date ∈ [today, today+6]` | 日期/时间 | 含今天，不含更早逾期 |
| 所有 | 所有活跃任务 | 分组/排序 | 不含完成/放弃/跳过/删除 |
| 已完成 | `status='completed'` 且未删除 | `completed_at DESC` | 含子任务 |
| 已放弃 | `status='abandoned'` 且未删除 | `abandoned_at DESC` | 可重新开始 |
| 垃圾桶 | `deleted_at IS NOT NULL` | `deleted_at DESC` | 可恢复/彻底删除 |
| 摘要 | 由查询条件动态生成 | 用户配置 | 不是任务列表 |

### 2.2 “今天”的边界

```text
today = 档案时区的当前日期（YYYY-MM-DD）
today 清单 = 活跃任务 AND start_date IS NOT NULL AND start_date <= today
```

- 逾期任务会出现在“今天”，并标记“已逾期 N 天”。
- 无日期任务**不**出现在“今天”，除非用户手动加入（设置日期为今天）。
- 已完成任务不出现；已完成在“已完成”清单。
- 重复任务的当前实例若逾期，仍出现在“今天”；下一周期是只读投影。

> 官方帮助文档只写“到期日为今天”。本复刻选择“包含逾期”，因为这是待办应用更常用的心智模型；后续可用真实账号验证再调整。

### 2.3 “最近 7 天”的边界

```text
最近 7 天 = 活跃任务 AND start_date BETWEEN today AND today + 6
```

- 含今天，共 7 个自然日。
- 不含逾期（逾期在“今天”和“所有”）。
- 不含无日期。

### 2.4 显示策略

每个智能清单可配置：

| 值 | 行为 |
|---|---|
| `show` | 始终显示 |
| `hide` | 始终隐藏 |
| `auto` | 有内容时显示，无内容时隐藏 |

- 收集箱不可隐藏/删除。
- 计数徽标显示该清单的活跃任务数；完成/垃圾等按对应规则计数。
- 在“今天/最近 7 天”中是否显示习惯、纪念日、专注记录，由设置项控制；v1 默认只显示任务。

### 2.5 子任务

- 智能清单默认包含所有层级任务。
- 列表展示时，子任务可以缩进在父任务下，也可以平铺；由视图设置决定。
- 父任务完成不自动完成子任务，除非用户显式选择“连同子任务”；规则见任务规格。
- 过滤器的 `parentId` 条件可用于只看顶层或某个父任务下。

## 3. 过滤器 DSL

### 3.1 结构

```json
{
  "version": 1,
  "op": "and",
  "children": [
    { "field": "projectId", "operator": "in", "value": ["project-work"] },
    {
      "op": "or",
      "children": [
        { "field": "tags", "operator": "all", "value": ["tag-focus", "tag-reading"] },
        { "field": "priority", "operator": "in", "value": [3, 5] }
      ]
    },
    { "field": "startDate", "operator": "between", "value": ["preset:today", "preset:next7days"] }
  ]
}
```

约定：

- `op`：`and` / `or`；最多嵌套 3 层。
- 叶子节点：`field` + `operator` + `value`。
- 空组无效；最多 50 个叶子条件。
- `version` 必填；未来 DSL 升级用于迁移。
- 前端只提供一层 AND/OR 组合；DSL 支持嵌套，便于导入/高级用户。

### 3.2 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `projectId` | string[] | 清单 ID |
| `tagIds` | string[] | 标签 ID |
| `priority` | number[] | 0/1/3/5 |
| `status` | string[] | open/completed/abandoned/skipped |
| `startDate` | date/preset | 开始日期 |
| `endDate` | date/preset | 结束日期 |
| `completedAt` | date/preset | 完成时间 |
| `createdAt` | date/preset | 创建时间 |
| `updatedAt` | date/preset | 修改时间 |
| `keyword` | string | 关键词 |
| `hasDate` | boolean | 是否有日期 |
| `pinned` | boolean | 是否置顶 |
| `parentId` | string/null | 父任务 |
| `kind` | `task`/`note` | 类型 |
| `estimateMinutes` | number | 预计时长（如有） |

### 3.3 操作符

| 操作符 | 适用 | 说明 |
|---|---|---|
| `eq` / `neq` | 所有 | 等于/不等于 |
| `in` / `notIn` | 枚举/多值 | 属于/不属于 |
| `between` | 日期/数字 | 闭区间 |
| `before` / `after` | 日期 | 早于/晚于 |
| `contains` | 文本 | 包含（大小写不敏感） |
| `isNull` / `isNotNull` | 可空字段 | 为空/不为空 |
| `all` / `any` / `none` | 标签 | 同时包含/任一/都不包含 |

### 3.4 日期预设

| 预设 | 解析 |
|---|---|
| `preset:today` | 今天 |
| `preset:tomorrow` | 明天 |
| `preset:yesterday` | 昨天 |
| `preset:next7days` | 今天 .. 今天+6 |
| `preset:next30days` | 今天 .. 今天+29 |
| `preset:overdue` | 早于今天 |
| `preset:noDate` | 无日期 |
| `preset:thisWeek` | 本周（按 weekStart） |
| `preset:thisMonth` | 本月 |

日期预设必须在**查询时**按当前档案时区解析，不能保存为固定日期。

### 3.5 默认过滤

- 默认排除 `deleted_at IS NOT NULL`。
- 默认排除 `completed` / `abandoned` / `skipped`，除非用户显式指定 `status`。
- 默认包含任务与笔记；用户可用 `kind` 限定。
- 关键词默认搜索标题 + 正文；v1 不含检查事项/评论（后续可配）。
- 结果按过滤器自己的排序配置；未配置时用视图默认排序。

### 3.6 校验

保存前必须：

1. 校验 DSL 结构与版本。
2. 校验字段/操作符组合合法。
3. 校验引用 ID 存在（清单/标签）。
4. 运行一次 dry-run 预览，显示命中数量。
5. 空条件或空结果时提示，但允许保存（用户可能先保存再调整）。

### 3.7 预览

- 预览显示前 50 条，避免大查询卡顿。
- 预览使用与正式查询相同的编译器，禁止两套逻辑。
- 预览结果不计入统计/成就。

## 4. 查询编译

### 4.1 伪代码

```text
compile(filter, profile):
  assert validate(filter)
  base = tasks WHERE profile_id = ? AND deleted_at IS NULL
  if not filterIncludesStatus(filter):
      base += AND status = 'open'
  return compileNode(filter, base)
```

`compileNode`：

- `and`：所有子节点用 AND 连接。
- `or`：所有子节点用 OR 连接，外层加括号。
- 叶子：按字段/操作符生成 SQL 片段；所有值参数化，禁止字符串拼接。
- 标签 `all`：对每个 tag 生成 `EXISTS`；`any`：一个 `EXISTS ... IN`；`none`：`NOT EXISTS`。
- 日期预设：先替换为具体日期，再生成比较。
- 关键词：`title LIKE ? OR content_md LIKE ?`，转义 `%`/`_`。
- 排序：白名单映射到列名，禁止用户输入列名。

### 4.2 性能

- 常用过滤条件必须有索引：`profile_id, status, deleted_at`、`start_date`、`completed_at`、`project_id`。
- 标签过滤走 `task_tag` + `tag_id` 索引。
- 关键词走 FTS5；短词回退 `LIKE`。
- 结果分页使用游标，不用大 offset。

### 4.3 保存的过滤器

```json
{
  "id": "filter-1",
  "name": "本周高优先级工作",
  "query": { ... },
  "sort": { "by": "priority", "direction": "desc" },
  "group": { "by": "project" }
}
```

- 侧边栏显示按 `sort_key` 排序；可置顶。
- 重命名/删除不影响任务。
- 导入旧版本 DSL 时执行迁移；无法迁移则提示重建。

## 5. 验收用例

| # | 场景 | 期望 |
|---|---|---|
| 1 | 今天有 1 个今天任务 + 1 个逾期任务 | “今天”显示 2 个，逾期有标记 |
| 2 | 无日期任务 | 不出现在“今天”，出现在“收集箱/所有” |
| 3 | 最近 7 天 | 含今天，不含逾期和无日期 |
| 4 | 已完成任务 | 只在“已完成”，不在“所有/今天” |
| 5 | 垃圾桶任务 | 只在“垃圾桶”，可恢复 |
| 6 | 收集箱 | 只显示收集箱活跃任务，不可隐藏 |
| 7 | 过滤器：工作 + 高优先级 | 只命中同时满足的任务 |
| 8 | 过滤器：标签 all | 必须同时有多个标签 |
| 9 | 过滤器：标签 any | 任一标签即可 |
| 10 | 过滤器：关键词 | 标题或正文命中 |
| 11 | 过滤器：日期预设 today | 按当前时区解析 |
| 12 | 过滤器：status 含 completed | 结果包含已完成，不受默认排除影响 |
| 13 | 过滤器：空条件 | 校验失败，提示补条件 |
| 14 | 过滤器：引用已删除清单 | 校验提示，不崩溃 |
| 15 | 搜索 + 过滤器 | 两个条件同时生效（AND） |
| 16 | 10 万任务 | 查询 < 150ms，分页稳定 |

4. 过滤器关键词是否覆盖检查事项/评论；v1 只覆盖标题+正文。
