# 重复规则规格 v1

> 配套：`docs/specs/schema-v1.sql`、`docs/specs/数据字典与Schema-v1.md`
> 目标：把“支持重复”变成可实现、可测试、可验收的规则
> 日期：2026-11-05
>
> 实现状态（2026-11-06）：`packages/recurrence` 已实现标准频率、月末/闰年钳制、结束条件、Ebbinghaus、自选日期、完成模式与下一周期计算，并有单测覆盖。2026 年法定节假日/调休数据已接入 `statutory_workday` / `statutory_holiday`；重复任务支持 `recurrence_exception` 的 override（仅此周期）、跳过此周期、恢复默认时间；“已跳过”智能清单可查看并恢复跳过周期；恢复较早周期时会自动把后续未完成周期标记为跳过，保证每个系列只有一个当前周期。农历重复转换尚未接入 UI。

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| 系列（Series） | 一套重复规则 + 模板字段 |
| 模板任务（Template） | 保存标题、正文、优先级、标签、检查事项等公共字段的任务行 |
| 实例（Occurrence） | 系列在某一天生成的任务行 |
| 当前实例 | 系列中唯一 `open` 的实例；未来周期是只读投影 |
| 锚点（Anchor） | 首次发生日期 `dtstart_date` / `dtstart_time` |
| 发生日期（Occurrence Date） | 实例在系列中的本地日期标识，`YYYY-MM-DD` |
| 到期重复（Due） | 下一周期按“计划日期”推进，拖延不影响 |
| 完成重复（Completion） | 下一周期按“完成日期”推进 |
| 自选日期（Selected Dates） | 显式列出一组日期 |

## 2. 数据模型

### 2.1 `recurrence_series`

| 字段 | 说明 |
|---|---|
| `mode` | `due` / `completion` / `selected_dates` |
| `rule_json` | 频率规则，见 2.2 |
| `timezone` | IANA；`fixed_zone` 时必填 |
| `dtstart_date` / `dtstart_time` | 首次发生；全天任务 `dtstart_time` 为空 |
| `end_type` / `end_date` / `end_count` | 结束条件 |
| `completed_count` | 已完成实例数（统计用） |
| `status` | `active` / `paused` / `ended` |

### 2.2 `rule_json`

```json
{
  "version": 1,
  "freq": "daily",
  "interval": 1,
  "byWeekday": [1, 2, 3, 4, 5],
  "byMonthDay": [1, 15, -1],
  "byMonth": [1, 12],
  "weekStart": 1,
  "lunar": { "month": 8, "day": 15, "leap": false, "includeLeapMonths": false },
  "selectedDates": ["2026-01-01", "2026-02-14"],
  "ebbinghaus": { "offsets": [0, 1, 3, 6, 14], "tailDays": 15 }
}
```

约定：

- `version` 必填；未来规则升级时用于迁移。
- `freq` 必填，取值：
  `daily` / `weekly` / `monthly` / `yearly` / `weekdays` / `weekend` /
  `statutory_workday` / `statutory_holiday` / `lunar_yearly` / `lunar_monthly` /
  `ebbinghaus` / `selected_dates`
- `byWeekday`：1=周一 … 7=周日（ISO）。
- `byMonthDay`：1–31，负数从月末倒数（-1=最后一天）。
- `byMonth`：1–12。
- `weekStart`：1=周一，7=周日；影响“周”的边界。
- 不需要的字段可省略；解析时使用默认值。
- 所有日期均为本地日期，禁止用 UTC 时间戳代替。

### 2.3 实例字段

| 字段 | 说明 |
|---|---|
| `recurrence_series_id` | 所属系列 |
| `occurrence_date` | 系列身份；同一系列内唯一 |
| `occurrence_index` | 从 0 开始的序号 |
| `start_date` / `start_time` | 展示时间；允许被“仅此周期”修改 |
| `series.status` | 系列结束后不再生成 |

> `occurrence_date` 是“系列中的位置”，不是“当前显示日期”。仅此周期改期后，`occurrence_date` 保持不变，`start_date` 改变。这样不会与后续周期冲突。

## 3. 时间与时区

### 3.1 两种时间模式

| 模式 | 语义 | 存储权威值 | 跨时区行为 |
|---|---|---|---|
| `floating`（固定时间） | 墙上时钟，例如“每天 9:00” | `start_date` + `start_time` | 仍是当地 9:00；重算 `start_at` |
| `fixed_zone`（固定时区） | 绝对时刻固定 | `start_at` + `timezone` | 保持原时区时刻；显示可对照本地 |

### 3.2 时区解析规则

- 展开重复时，按本地日历日期逐日推进，**不要用“加 24 小时”**。
- `floating`：使用当前档案时区解析 `date + time`。
- `fixed_zone`：使用系列 `timezone` 解析。
- 全天任务：没有时区；`start_date` 即事实。

### 3.3 DST（夏令时）

- **不存在的本地时间**（春季跳过）：向后顺移到下一个有效时刻。例：02:30 不存在 → 03:30。
- **重复的本地时间**（秋季回拨）：选择较早的偏移（第一次出现）。
- 上述行为写入测试；不同平台库默认行为可能不同，必须显式实现。
- 推荐测试时区：`America/New_York`、`Europe/Berlin`、`Australia/Lord_Howe`（30 分钟 DST）。

## 4. 各重复类型算法

所有算法输出“本地日期 + 本地时间”的候选集合，再统一过滤、去重、排序。

### 4.1 每天（daily）

```text
candidate(n) = dtstart_date + n * interval 天
n = 0, 1, 2, ...
```

### 4.2 每周（weekly）

```text
以 dtstart 所在周为第 0 周（周起始 = weekStart）
每 interval 周，取 byWeekday 中的星期
默认 byWeekday = [dtstart 的星期]
过滤 candidate >= dtstart_date
```

示例：dtstart 周三，`byWeekday=[1]`，interval=1 → 首次是下周一，不是本周一。

### 4.3 每月（monthly）

```text
以 dtstart 所在月为第 0 月
每 interval 月，取 byMonthDay
默认 byMonthDay = [dtstart 的日]
```

月末规则：

- `byMonthDay=31`，当月只有 30 天 → **钳制到最后一天（30 日）**。
- `byMonthDay=-1` → 当月最后一天。
- `byMonthDay=30`，2 月 → 钳制到 2 月最后一天。
- 多个 `byMonthDay` 去重、排序。

### 4.4 每年（yearly）

```text
以 dtstart 所在年为第 0 年
每 interval 年，取 byMonth × byMonthDay 组合
默认 byMonth = [dtstart 月]，byMonthDay = [dtstart 日]
```

- 2 月 29 日在非闰年 → **钳制到 2 月 28 日**。
- 多个组合去重。

### 4.5 每周工作日（weekdays）

等价于：

```json
{ "freq": "weekly", "interval": 1, "byWeekday": [1,2,3,4,5] }
```

### 4.6 每周末（weekend）

等价于：

```json
{ "freq": "weekly", "interval": 1, "byWeekday": [6,7] }
```

### 4.7 法定工作日（statutory_workday）

判定 `isWorkday(date)`：

1. 查 `holiday_calendar`：`type='workday'` → 上班；`type='holiday'` → 不上班。
2. 无记录：周一至周五上班，周六周日不上班。

说明：

- 包含调休上班日（例如春节前的周六）。
- `interval` 必须为 1；大于 1 时按“每 N 个工作日”解释（v1 不支持，解析报错）。
- 数据缺失年份时降级为周一至周五，并在 UI 提示“节假日数据未更新”。

### 4.8 法定节假日（statutory_holiday）

判定 `isHoliday(date)`：

1. 查表：`type='holiday'` → 放假；`type='workday'` → 不放。
2. 无记录：周六周日放假，周一至周五不放。

说明：

- 只覆盖国家法定放假安排；不自动包含年假、公司假。
- 数据缺失年份时降级为周末，并提示。

### 4.9 农历每年（lunar_yearly）

- 使用成熟农历库（建议 `lunar-typescript`）做农历→公历转换。
- `lunar.month` / `lunar.day`；默认取 `dtstart` 对应的农历月/日。
- `lunar.leap`：
  - `false`：使用普通月；该年没有普通月？不会发生。
  - `true`：只使用闰月；该年没有该闰月 → 跳过该年。
- 日期不存在（如农历小月没有三十）→ **钳制到当月最后一天**。
- 除夕：v1 不提供“农历年最后一天”快捷项；用户可手动选择农历 12/29 或 12/30。v1.1 增加 `lastDayOfLunarYear`。
- 跨农历年边界时，按农历年推进，不按公历年。

### 4.10 农历每月（lunar_monthly）

- 每个农历月的 `lunar.day`。
- 默认**跳过闰月**；`includeLeapMonths=true` 时闰月也重复。
- 日期不存在 → 钳制到当月最后一天。
- 例：农历每月初一、十五。

### 4.11 艾宾浩斯（ebbinghaus）

官方文案：

> 重复周期按照 1，2，4，7，15，15，15…… 循环；在学习当天（一）、第二天（二）、第四天（四）、第七天（七）复习。

本复刻采用**“第几天”解释**：

```text
offsets = [0, 1, 3, 6, 14]   // 相对锚点的天数：第 1/2/4/7/15 天
之后每 15 天：+15, +15, ...
```

即出现日期：第 1、2、4、7、15、30、45… 天。

> 这是官方文档的歧义点。另一种解释是“间隔 1,2,4,7,15 天”（第 1/2/4/8/15/30 天）。v1 先按“第几天”实现，并在设置页说明；后续可用真实账号验证再调整。

- 默认按到期推进；用户完成晚了不改变后续日期。
- 若允许完成重复，锚点改为完成日，但 v1 不提供该组合。
- `end_count` 按发生序号计算；`end_date` 按发生日期计算。

### 4.12 自选日期（selected_dates）

- `mode='selected_dates'`，`rule_json.selectedDates` 为日期数组。
- 去重、排序、过滤 `< dtstart_date` 的日期。
- 不参与“完成重复”。
- 结束条件仍可用。

## 5. 三种模式

### 5.1 到期重复（due）

- 下一实例 = 规则中“当前 `occurrence_date` 之后的下一个候选日期”。
- 完成时间不影响下一周期。
- 例：每月 1 日，3 日才完成 → 下期仍是下月 1 日。

### 5.2 完成重复（completion）

- 下一实例 = 从**完成时的本地日期**开始，按规则间隔推进。
- 保留原 `start_time`。
- 例：每 3 天健身，周五完成 → 下次周一（间隔 3 天，按本地日历计算）。
- 若规则含 `byWeekday` / `byMonthDay`：
  1. 先算完成日 + interval 的“目标日期”；
  2. 再取该日期之后第一个满足规则的候选日。
- 若目标日期 <= 完成时刻，继续推进，直到严格大于完成时刻；最多 1000 次，防死循环。
- `selected_dates` 不支持 completion 模式。

### 5.3 自选日期（selected_dates）

- 只按显式日期生成。
- 不支持 completion 模式。

## 6. 展开算法

### 6.1 输入输出

```text
expand(series, windowStart, windowEnd, profileTimezone, options)
  -> Occurrence[]
```

- `windowStart` / `windowEnd`：本地日期，左闭右开或闭区间需统一；建议 `[start, end)`。
- 返回项包含：`occurrenceDate`、`occurrenceIndex`、`startDate`、`startTime`、`timezone`、`isException`。
- 默认最多返回 10,000 条；超过则截断并记录告警。

### 6.2 伪代码

```text
function expand(series, windowStart, windowEnd, profileTz):
  rule = parseRule(series.rule_json)
  validate(rule, series.mode)

  tz = series.mode == 'fixed_zone' ? series.timezone : profileTz
  candidates = []

  for each period from dtstart to windowEnd:
    for each localDate in candidatesInPeriod(rule, period):
      if localDate < series.dtstart_date: continue
      if localDate < windowStart: continue
      if localDate >= windowEnd: break
      if endReached(series, localDate): break
      candidates.add(localDate)

  candidates = dedupeAndSort(candidates)
  occurrences = []
  for i, date in candidates:
    index = occurrenceIndex(series, date)
    exceptions = loadExceptions(series.id, date)
    if exceptions.action == 'skip': continue
    occurrence = buildOccurrence(series, date, index, exceptions.override)
    occurrences.add(occurrence)
    if occurrences.size >= 10000: break

  return occurrences
```

### 6.3 结束条件

| 条件 | 判定 |
|---|---|
| `never` | 不结束 |
| `date` | `occurrence_date > end_date` 时停止；`end_date` 当天仍发生 |
| `count` | `occurrenceIndex >= end_count` 时停止；`end_count` 是总次数（含首次） |

- `end_count` 基于“发生序号”，跳过（skip）也消耗次数。
- `completed_count` 只统计实际完成，不用于结束判定。
- 修改规则后，`end_count` 是否重新计数？v1 决策：保持原 `occurrence_index`，不重排历史；若用户选择“从今天起重置”，则新建系列。

## 7. 实例生命周期

### 7.1 完成（complete）

```text
complete(task):
  assert task.status == open
  mark task completed, completed_at = now
  if task.series_id == null: return

  series = load(task.series_id)
  series.completed_count += 1

  if endReachedAfter(series, task.occurrence_index):
    series.status = ended
    return

  nextDate = nextAfter(series, task.occurrence_date, mode, now)
  nextDate = applyCatchUp(series, nextDate, now)
  if nextDate == null: series.status = ended; return

  createNextOccurrence(series, nextDate)
```

`createNextOccurrence`：

- 复制模板字段：标题、正文、项目、分组、优先级、标签、预计时长、附件引用。
- 复制检查事项定义，重置 `completed=0`。
- 复制子任务树，重置状态（如果产品选择支持；v1 建议支持，深度沿用 5 级）。
- 不复制评论、动态。
- 重新计算提醒 `trigger_at`。
- `occurrence_date=nextDate`，`occurrence_index=prev+1`。
- 应用例外：若 nextDate 在 `recurrence_exception` 中为 `skip`，继续取下一个。
- 应用覆盖：若为 `override`，用 `override_json` 覆盖字段。

### 7.2 跳过（skip）

```text
skip(task):
  mark task status = skipped, abandoned_at = now
  series = load
  nextDate = nextAfter(series, task.occurrence_date)
  if nextDate == null or endReached: series.status = ended
  else createNextOccurrence(series, nextDate)
```

- 跳过不计入 `completed_count`，但消耗 `occurrence_index`。
- 被跳过的实例保留在数据库中，默认不在列表中显示；可在“已放弃/历史”查看。

### 7.3 仅此周期修改（override）

- 用户修改当前实例的日期、时间、标题、优先级、标签等。
- `occurrence_date` 保持不变；`start_date` / `start_time` 可改。
- 写入 `recurrence_exception(action='override', override_json=changedFields)`。
- 系列规则不变；下一周期仍按原规则推进。
- 如果用户把日期改到与下一周期重合，允许；日历上显示为两个任务（不同 `occurrence_date`）。

### 7.4 修改未来所有（split series）

- 从当前实例开始，旧系列截断：`old.end_type='date'`，`old.end_date=当前 occurrence_date 前一天`。
- 新建系列：`dtstart=当前 occurrence_date`，`rule=新规则`，`template=当前任务`。
- 当前实例与未来实例指向新系列。
- 已生成的未来实例（如果有）重新绑定；v1 只保留当前实例，因此只需改当前。
- 例外记录不迁移；如需要，按日期复制。

### 7.5 修改全部（all）

- 更新模板任务与 `series.rule_json`。
- 当前实例同步更新未被“仅此周期”覆盖的字段。
- 未来虚拟实例使用新规则。
- 已存在的例外保留；日期不再存在的例外标记为孤立，后台清理。
- 修改 `dtstart` 时，`occurrence_index` 重新计算？v1 决策：不重排历史，新规则从当前日期起生效；`dtstart` 仅用于展开锚点。

### 7.6 删除

| 操作 | 行为 |
|---|---|
| 删除当前实例（仅此） | 视为跳过：`status=skipped`，生成下一实例 |
| 删除整个系列 | 软删除模板、系列、当前实例；`series.status=ended` |
| 删除历史实例 | 只软删除该任务，不影响系列 |
| 恢复历史实例 | 恢复为独立任务（清空 `series_id`），避免与系列冲突 |
| 恢复当前实例 | 若系列仍有 open 实例，恢复为独立任务；否则重新绑定 |

### 7.7 取消完成（uncomplete）

1. 若下一实例存在，且 `status='open'`、`updated_at == created_at`（未被修改）：
   - 删除下一实例；重新打开当前实例；`completed_count -= 1`。
2. 若下一实例已被修改/完成：
   - 保留下一实例；重新打开当前实例；提示“可能出现两个未完成实例”。
3. 若系列已 `ended`：重新打开当前实例，`series.status='active'`，`completed_count -= 1`。

## 8. 物化与补偿策略

### 8.1 只物化当前实例

- 每个系列最多一个 `open` 实例（当前周期）。
- 未来周期由日历/时间线按需展开，是**只读投影**。
- 这与官方“重复任务未完成前不能操作后续周期”一致。
- 未来投影不能直接完成/修改；点击时提示先处理当前周期，或提供“跳过当前并进入该周期”。

### 8.2 完成后的追赶（catch-up）

场景：每天重复的任务，用户 90 天没打开应用，今天完成当前实例。

决策：

- `due` 模式：下一实例取“今天或之后第一个候选日期”，**不为过去 90 天补生成 90 个任务**。
- `completion` 模式：下一实例 = 完成日 + interval；若仍在过去，继续推进到今天之后。
- 追赶会消耗 `occurrence_index`；若越过 `end_count` / `end_date`，系列结束。
- 被跳过的周期可在统计中记为“错过”，但不生成任务行。

### 8.3 启动对账

应用启动时：

1. 对每个 `active` 系列，检查是否有 `open` 实例。
2. 若没有：按最后完成/跳过日期生成下一个；若无历史，按 `dtstart` 生成。
3. 若多于一个：保留最早的一个，其余软删除并记录 `activity`（异常修复）。
4. 检查 `open` 实例的 `occurrence_date` 是否与系列规则一致；不一致则记录告警，不自动改期。
5. 重算所有 `pending` 提醒的 `trigger_at`，扫描已过期提醒。

### 8.4 提醒

- 只为已物化的当前实例创建提醒。
- 未来投影不创建提醒；当前实例完成后，下一实例创建时再生成。
- 若用户希望“提前几天提醒下一次”，在实例创建时按偏移计算；这仍只针对当前实例。

## 9. 边界情况

| 场景 | 决策 |
|---|---|
| 每月 31 日，2 月 | 钳制到 2 月最后一天 |
| 每年 2 月 29 日，非闰年 | 钳制到 2 月 28 日 |
| 农历小月没有三十 | 钳制到当月最后一天 |
| 农历闰月不存在 | `leap=true` 时跳过该年；`leap=false` 用普通月 |
| 法定节假日数据缺失年份 | 降级为周末规则，UI 提示 |
| 调休周六上班 | `statutory_workday` 包含；`statutory_holiday` 排除 |
| DST 春季 02:30 不存在 | 顺移到 03:30 |
| DST 秋季 01:30 重复 | 选较早偏移 |
| 完成时间早于计划时间 | `due` 不影响下期；`completion` 从完成时间算 |
| 完成时间晚于下期 | 追赶策略，不补生成全部错过周期 |
| 修改当前实例日期到下一周期 | 允许；两个实例并存 |
| 修改系列规则 | 只影响当前与未来；历史不改 |
| 删除系列后恢复 | 恢复为独立任务，不恢复系列 |
| 取消完成时下一实例已修改 | 保留下一实例，提示重复风险 |
| 同一系列同一天多个候选 | 去重，只保留一个 |
| 规则产生超过 10000 条 | 截断并告警；提示缩小范围 |
| 时区变化 | `floating` 重算；`fixed_zone` 不变 |
| 全天任务跨时区 | 始终按本地日期，不随时区偏移 |
| 系列结束条件为 count，跳过多个周期 | 跳过消耗次数，按序号结束 |
| 自选日期包含重复项 | 去重 |
| 自选日期早于 dtstart | 忽略 |

## 10. 测试计划

### 10.1 属性测试（fast-check）

对随机生成的规则验证：

1. 输出日期严格递增、无重复。
2. 所有输出 `>= dtstart`。
3. 所有输出在窗口内。
4. `end_count` 时输出数量不超过限制。
5. `end_date` 时输出不超过截止日。
6. 展开在有限步内终止（不会死循环）。
7. 同一输入多次展开结果一致（纯函数）。
8. 时区解析结果可逆（本地日期 + 时间 + 时区 → UTC → 本地）。

## 11. 开放问题

1. 艾宾浩斯到底是“第 1/2/4/7/15 天”还是“间隔 1/2/4/7/15 天”？需用真实账号验证。
2. 农历每月是否包含闰月？v1 默认不包含，需确认官方行为。
3. 法定节假日是否包含调休上班日的“前后周末”？以年度数据为准，需确认数据源。
4. 未来周期是否允许提前完成？v1 不允许，需确认官方。
5. 取消完成后，下一实例的保留策略是否符合用户预期？
6. 修改“未来所有”时，历史例外的迁移策略是否需要更细。
7. 完成重复在 `byWeekday` / `byMonthDay` 下的语义，官方未明确；v1 采用“完成日 + interval 后找下一个匹配日”。
8. 重复任务完成时是否复制子任务/附件/评论？v1 决策：复制子任务和附件引用，不复制评论。
